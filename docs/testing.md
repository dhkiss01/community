댓글 API에는 위 댓글 조회 외에 게시글 존재 확인 쿼리 1회가 추가됩니다. 쿼리 수 검사는 H2에서 수행했고, MySQL에서는 별도의 실제 HTTP 시나리오를 실행했습니다.

테스트가 발견한 로컬 CORS 오류, 읽기 전용 댓글 조회의 불필요한 잠금, 제목 링크의 접근성 이름을 수정한 뒤 다시 통과시켰습니다. 사용자 입력의 HTML 태그가 텍스트로 표시되는 것도 브라우저에서 확인했습니다.

## 직접 실행하기

외부 서비스 없이: `community-BE`에서 `./gradlew test`, `community-FE`에서 `npm test`.

전체 로컬 서비스가 실행 중일 때 저장소 루트에서 `node scripts/integration-test.mjs`를 실행합니다. 브라우저 검사는 `community-FE`에서 `npm run test:e2e`입니다. 실패한 브라우저 테스트의 trace는 `test-results`에 남습니다.

`ELASTICSEARCH_CONTAINER=community-elasticsearch-local node scripts/recovery-test.mjs`는 **ELASTICSEARCH_CONTAINER로 지정한 로컬 테스트용 Elasticsearch 컨테이너를 실제로 중지했다가 다시 켭니다.** 다른 테스트와 동시에 실행하지 마세요. 검색 중단 중 게시글 저장, 검색 503, 복구 후 outbox 재처리를 확인합니다.

화면 캡처는 로컬 샘플 데이터를 넣은 상태입니다. 실제 사용자 사용성 시험, 운영 트래픽 부하 시험, 운영 AWS/S3 연결 및 GitHub Actions 원격 실행은 이 기록의 범위에 포함하지 않습니다.

게시판 탭은 제목에 직관이나 분석이라는 단어가 없는 동일한 내용의 글로 검증했습니다. 분류별 목록, 해당 게시판 안에서의 검색, 검색 초기화 후 분류 유지, 글쓰기 화면의 게시판 자동 선택을 데스크톱과 모바일에서 확인했습니다. 브라우저 탭 제목은 모든 화면에서 더그아웃으로 고정합니다.

목록을 표 형태로 변경한 뒤 브라우저 테스트 6개를 다시 통과했습니다. Chrome에서 데스크톱과 모바일 화면을 직접 열어 제목 잘림, 열 정렬, 가로 넘침을 확인했습니다.

## 저장소 재점검

파일 삭제에 맞춰 로컬 실행 안내와 CI를 정리했습니다. 검증 workflow는 GitHub Actions의 MySQL 서비스와 별도의 Elasticsearch 테스트 컨테이너를 사용합니다.

Java 테스트에서 토큰 만료시간, 토큰 회전과 재사용 차단, 로그아웃, 잘못된 API 경로의 응답을 확인했습니다. 실제 MySQL에서는 동시 재발급과 동시 로그인도 검증했습니다. 프런트엔드 테스트는 빈 게시판의 작성 버튼과 회원가입 후 작성 화면 복귀, 로그아웃 시 쿠키 삭제를 포함해 8개를 통과했습니다.

Spring Cloud AWS는 Spring Boot 3.5에 맞는 3.4.2로 변경했습니다. [공식 호환표](https://github.com/awspring/spring-cloud-aws#compatibility-with-spring-project-versions)를 기준으로 선택하고 이미지 빌드와 실행을 확인했습니다.

런타임 npm 의존성을 정리하고 패치한 뒤 `npm audit --omit=dev` 결과는 0건입니다. Express가 사용하는 qs는 취약점 수정 버전을 사용하도록 override했습니다. 이 결과는 검사 시점의 알려진 취약점에 대한 것입니다.

프런트엔드 Helm chart의 lint와 template 렌더링을 통과했습니다. 운영 클러스터 적용과 S3 연결은 수행하지 않았습니다.
